1

Définition & domaines

La virtualisation est l'ensemble des techniques qui permettent de faire fonctionner plusieurs systèmes d'exploitation ou environnements sur une même machine physique, en abstraisant les ressources (CPU, mémoire, stockage, réseau).

Elle repose sur trois éléments : abstraction des ressources, répartition entre environnements, création d'environnements virtuels isolés.

DomainePrincipeExemple
ServeursPlusieurs serveurs virtuels sur un serveur physique.ESXi, Hyper-V, Proxmox.
Postes de travailBureau virtuel exécuté à distance.VDI (Virtual Desktop Infrastructure), Citrix, Horizon.
ApplicationsIsoler une application de l'OS.Wine, ThinApp, App-V, conteneurs applicatifs.
RéseauFonctions réseau en logiciel (SDN).vSwitch, NSX, VLAN, VXLAN.
StockageAgréger et abstraire les ressources de stockage.Datastore, vSAN, SAN, NAS.
Vocabulaire

Hôte : machine physique. Invité (guest) : OS installé dans la VM. VM : machine virtuelle. Hyperviseur : couche logicielle de virtualisation. VMM : Virtual Machine Monitor, synonyme d'hyperviseur.

La virtualisation a été popularisée par IBM dans les années 1960, puis relancée par VMware, Xen, KVM et les conteneurs.

2

Avantages & consolidation

Avantages
  • Consolidation et meilleure utilisation des ressources.
  • Réduction des coûts (matériel, énergie, climatisation, espace, personnel).
  • Déploiement rapide, agilité, automatisation.
  • Isolation des environnements.
  • Haute disponibilité, reprise après sinistre, PRA.
  • Tests, snapshots, clones, templates.
  • Support de systèmes legacy.
  • Green IT.
Inconvénients
  • Surcoût de performance (couche d'abstraction).
  • Complexité de gestion et de compétences.
  • Point de défaillance unique (serveur, stockage, hyperviseur).
  • Licences et coûts cachés.
  • Sécurité : surface d'attaque et mouvements latéraux.
  • Dépendance au fournisseur.
  • Planification de capacité difficile.

Consolidation

Consolidation de serveurs : regrouper plusieurs serveurs physiques sous-utilisés sur moins de serveurs, grâce aux VM, pour optimiser les ressources et réduire les coûts.

Consolidation du stockage : centraliser les capacités dispersées en une infrastructure partagée (SAN/NAS/vSAN), pour simplifier la gestion, améliorer l'efficacité et faciliter la protection des données.

Le taux de consolidation est le rapport entre le nombre de serveurs physiques initiaux et le nombre d'hôtes après virtualisation. On parle aussi de P2V pour la migration physique → virtuel.

Les 3 schémas à savoir dessiner
Type 1 : Matériel → Hyperviseur → VM1 | VM2 | VM3

Type 2 : Matériel → OS hôte → Hyperviseur → VM1 | VM2

Conteneur : Matériel → OS hôte (noyau partagé) → Moteur → C1 | C2 | C3

Type 1 = natif, bare metal. Type 2 = hébergé, nécessite un OS. Conteneur = pas d'OS invité, un seul noyau partagé.

Virtualisation imbriquée (nested) : faire tourner un hyperviseur dans une VM. Exemple : ESXi installé dans Proxmox ou VMware Workstation, pour un lab. Il faut exposer les extensions CPU (VT-x/AMD-V).

4

Réseau virtuel

Le vSwitch

Un commutateur virtuel relie les VM entre elles et au réseau physique. Il fonctionne comme un switch : ports, VLAN, uplinks, port groups. Il est interne à l'hôte (vSwitch standard) ou distribué et centralisé par vCenter (vDS).

  • Port group : regroupement de ports avec une politique (VLAN, sécurité, teaming).
  • Uplink : carte physique de l'hôte reliée au switch physique.
  • VMkernel : interface du noyau ESXi pour la gestion, vMotion, iSCSI, NFS, vSAN.
  • VLAN : segmentation logique du trafic.
  • MTU : à aligner avec le switch physique pour les jumbo frames.

Les 3 types de réseau VMware

TypeFonctionnementAccèsUsage
BridgedLa VM est connectée directement au réseau physique, avec sa propre IP sur le même subnet que l'hôte.Réseau local + Internet.Serveur, tests réseau, visibilité directe.
NATLa VM sort via l'hôte, qui fait la traduction d'adresse ; elle n'est pas visible directement de l'extérieur.Internet, pas d'entrant sans redirection.Poste de travail, tests, isolation.
Host-onlyRéseau privé entre la VM et l'hôte uniquement.Hôte ↔ VM, pas d'Internet.Lab isolé, tests de sécurité.

Interne (VM-to-VM sans hôte) existe aussi selon les hyperviseurs ; VMware parle de host-only et de LAN segments.

Dépannage réseau ESXi

  1. Vérifier les cartes physiques et les uplinks (câble, switch, link).
  2. Vérifier l'association au vSwitch et au port group (VLAN, MTU).
  3. Vérifier que le port du switch physique est actif et autorise le VLAN.
  4. Contrôler le VMkernel et la passerelle ; tester avec vmkping.
  5. Consulter esxcli network nic list, esxcli network vswitch standard list, esxcli network ip interface list.

Migrations, snapshots, clones

MigrationDe → versObjectif
P2VPhysique → virtuelConsolider, moderniser, réduire le matériel.
V2VVirtuel → virtuel (autre hyperviseur)Changer de plateforme, éviter le verrouillage.
V2PVirtuel → physiqueRepasser sur du matériel dédié (rare).

Migration à chaud : VM allumée, sans interruption (vMotion). Migration à froid : VM arrêtée ou suspendue. vMotion : hôte à hôte. Storage vMotion : datastore à datastore. Les deux peuvent être combinés.

Snapshot

Capture l'état du disque, de la mémoire et de la configuration à un instant T. Utile avant une mise à jour ou un test. Ce n'est pas une sauvegarde : il dépend du datastore et de la VM ; une chaîne longue dégrade les performances et consomme de l'espace. Il faut consolider les snapshots après usage.

Clone & template

  • Clone : copie complète d'une VM (peut être liée ou complète).
  • Template : modèle non modifiable ; déploiement rapide et standardisé.
  • OVF/OVA : format portable d'appliance virtuelle.
Pièges QCM

On peut migrer une VM allumée (vrai/faux : faux, on peut). Type 2 n'est pas natif. Un snapshot n'est pas une sauvegarde. Un datastore peut être étendu. Proxmox a une interface web, pas seulement CLI.

Conteneurs & Docker

Un conteneur est une unité logicielle isolée qui embarque l'application et ses dépendances, mais partage le noyau de l'hôte. Il est plus léger et démarre plus vite qu'une VM.

VMConteneur
OS invitéComplet, par VM.Aucun ; partage du noyau.
IsolationForte (matériel virtualisé).Plus faible (processus isolé).
PoidsGo.Mo.
DémarrageMinutes.Secondes.
DensitéFaible.Élevée.
UsageOS différents, isolation forte.Microservices, CI/CD, applications portables.

Namespaces & cgroups

  • Namespaces : isolation de ce que le processus voit (PID, réseau, montages, UTS, IPC, utilisateurs).
  • cgroups : limitation et répartition des ressources (CPU, mémoire, I/O).

Docker n'est pas une technologie de virtualisation matérielle : c'est une plateforme de conteneurisation basée sur les primitives Linux (namespaces, cgroups, capabilities).

Docker

Docker est une plateforme open source pour créer, déployer et exécuter des applications dans des conteneurs. Architecture : client Docker → daemon Docker → containerd → runc → conteneur.

TermeDéfinition
ImageModèle read-only composé de couches (code, dépendances, OS de base).
ConteneurInstance exécutable d'une image, avec une couche writable.
DockerfileFichier texte décrivant la construction d'une image.
RegistreBibliothèque d'images (Docker Hub, GHCR, registre privé).
VolumeStockage persistant géré par Docker, survit à la suppression du conteneur.
Bind mountRépertoire de l'hôte monté dans le conteneur.

Cycle de vie d'un conteneur

docker run : crée et démarre. docker stop : arrête (les données du volume persistent, la couche writable aussi tant que le conteneur existe). docker rm : supprime le conteneur → les données de la couche writable sont perdues, les volumes persistent.

Processus de docker run

Le client envoie la requête au daemon. Le daemon vérifie si l'image existe localement ; sinon il la télécharge depuis le registre. Il crée un conteneur (couche writable), configure le réseau et les volumes, puis démarre le processus. Sans -d, le terminal reste attaché.

Créer une image personnalisée

  • docker build -t monimage . : construit à partir d'un Dockerfile.
  • docker commit conteneur monimage : fige un conteneur modifié en image (rapide, mais moins reproductible).
  • docker pull récupère une image existante ; il ne la crée pas. docker run ne crée pas une image.
Piège de correction

Le corrigé 2025 cite docker build, docker pull et docker run pour « créer une image ». La réponse rigoureuse est docker build (et docker commit). Si le correcteur attend deux commandes, cite docker build et docker commit en expliquant la différence.

Réseaux Docker

  • bridge (par défaut) : réseau privé, NAT vers l'hôte.
  • host : le conteneur partage la stack réseau de l'hôte.
  • none : pas de réseau.
  • overlay : multi-hôtes (Swarm).
  • macvlan : adresse MAC/IP propre sur le réseau physique.

Docker Compose

Docker Compose décrit une application multi-conteneurs dans un fichier docker-compose.yml. Il crée un réseau commun, démarre les services dans l'ordre des dépendances et facilite le développement.

version: "3.8"
services:
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: example
      MYSQL_DATABASE: wordpress
    volumes:
      - db_data:/var/lib/mysql
  wordpress:
    image: wordpress:latest
    depends_on:
      - db
    ports:
      - "8088:80"
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_PASSWORD: example
volumes:
  db_data:
CléRôle
servicesListe des conteneurs.
image / buildImage à utiliser ou Dockerfile à construire.
portsMapping hôte:conteneur.
environmentVariables d'environnement.
volumesPersistance des données.
depends_onOrdre de démarrage (pas de healthcheck implicite).
networksRéseaux partagés.
restartPolitique de redémarrage.

Commandes : docker compose up -d (démarre en arrière-plan), docker compose down (arrête et supprime), docker compose ps, docker compose logs -f, docker compose exec service bash, docker compose build.

Question type

« Expliquez la structure et le rôle du fichier docker-compose.yml. » Réponse : version, services, image/build, ports, volumes, environnement, dépendances ; il permet de décrire et lancer une application multi-conteneurs de façon reproductible. Commande : docker compose up -d.

Orchestration & sécurité

Orchestration

À grande échelle, il faut gérer le placement, le scaling, la disponibilité, le réseau et les mises à jour des conteneurs.

OutilRôle
KubernetesStandard de facto : pods, services, deployments, scaling, self-healing.
Docker SwarmOrchestration native Docker, plus simple.
NomadOrchestrateur HashiCorp, multi-workloads.
PortainerInterface de gestion Docker/Kubernetes.
OpenShiftPlateforme Kubernetes d'entreprise (Red Hat).

Sécurité des conteneurs

  • Image de base minimale, à jour, scannée (Trivy, Clair).
  • Utilisateur non-root, read-only filesystem, pas de --privileged.
  • Secrets gérés (Docker secrets, Vault), pas dans l'image.
  • Limites de ressources (cgroups), network policies.
  • Isolation : ne pas partager le socket Docker, namespaces utilisateur.
  • Noyau de l'hôte à jour : une faille noyau affecte tous les conteneurs.
  • Registry privé, signature d'images, scan CI/CD.
Isolation ≠ VM

Un conteneur partage le noyau : une évasion de conteneur peut compromettre l'hôte. Pour des charges de travail non fiables ou des OS différents, la VM reste plus isolée.

Questions de TP

Créer une VM sur ESXi

1) Uploader l'ISO sur un datastore. 2) Créer une VM : nom, guest OS, CPU/RAM, disque, réseau. 3) Monter l'ISO, démarrer, installer l'OS. 4) Installer VMware Tools. 5) Vérifier réseau, stockage, snapshots.

Créer un commutateur virtuel

Networking → Virtual switches → Add. Choisir les uplinks (NIC physiques), le MTU, les ports. Créer un port group, définir le VLAN et les politiques de sécurité. Vérifier la connectivité avec vmkping.

Déployer une VM depuis un OVF

File → Deploy OVF Template, choisir l'URL ou le fichier, nommer, sélectionner le datastore, le réseau, les options de disque (thin/thick), puis power on. Vérifier les VMware Tools et la configuration réseau.

Intérêt d'un snapshot + exemple

Point d'état temporaire avant une mise à jour ou un test. Exemple : snapshot avant un patch critique ; si l'application ne démarre plus, revert. Ce n'est pas une sauvegarde : il faut consolider et sauvegarder séparément.

X2X : principe et exemples

Terme générique pour toute migration : P2V (physique vers virtuel), V2V (virtuel vers virtuel), V2P (virtuel vers physique), P2P. On convertit le format de disque, les pilotes et la configuration. Outils : VMware Converter, virt-v2v.

Virtualisation imbriquée

Faire tourner un hyperviseur dans une VM. Exemple : ESXi dans Proxmox ou VMware Workstation. Nécessite d'exposer VT-x/AMD-V à la VM. Utile pour les labs, la formation, les tests de clusters.

Copier un seul disque d'une banque de données

Sélectionner le fichier VMDK de la VM. Pour un datastore bloc sous ESXi, le format est VMFS.

Docker Compose WordPress / MySQL

Voir le fichier de la section 11. Le service db utilise un volume db_data pour persister les données ; wordpress dépend de db et expose 8088:80. Commande : docker compose up -d.

Terme pour l'OS dans une VM

Système invité (guest).

Consolidation de serveurs et de stockage

Serveurs : regrouper plusieurs serveurs physiques sur moins d'hôtes via la virtualisation. Stockage : centraliser les capacités dispersées en une infrastructure partagée (SAN/NAS/vSAN).

Rôle du vSwitch

Connecter les VM entre elles et au réseau physique, avec VLAN, port groups et politiques de sécurité.

Dépannage réseau ESXi

V2V, P2V, template, migration à froid

Pourquoi perd-on les données d'un conteneur ?

Lorsqu'on supprime le conteneur (docker rm), la couche writable est détruite. Les volumes persistent ; un bind mount persiste aussi.

Objectif de la conteneurisation

Accélérer le développement, les tests et le déploiement, garantir la portabilité et l'isolation des dépendances.

Deux commandes pour créer une image

docker build -t image . et docker commit conteneur image. docker pull récupère une image existante.

Orchestrateur de conteneurs

Kubernetes (standard), Docker Swarm, Nomad, OpenShift ; Portainer pour la gestion.

Quel fichier pour copier un disque VM ?

VMDK. Sous ESXi, le datastore bloc est en VMFS.
